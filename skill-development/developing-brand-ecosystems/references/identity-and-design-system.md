# Identity and design system

## System layers

Define the smallest useful set:

- naming and signature hierarchy;
- logo/mark variants and usage contexts;
- color roles with accessible digital combinations and production values;
- typography roles, weights, fallbacks, licenses, and loading policy;
- grid, spacing, scale, shape, imagery, icons, data visualization, and motion principles;
- components, templates, content density, states, and do/don't examples.

## Source hierarchy

Keep editable sources, approved production masters, derived exports, previews, and process archive visibly separate. Convert typography to outlines for external logo masters when appropriate; retain editable construction sources internally.

Store font license text with distributed font files. Record owners and approval status for third-party images, audio, icons, and type.

## Existing identity

Start with recognizable codes worth preserving. Fix execution defects inside the existing language. Propose a redesign only when requested or when evidence shows the system cannot meet product, accessibility, production, or positioning requirements.

## Validation

Check small-size legibility, monochrome use, contrast, zoom, responsive crops, safe areas, export dimensions, file naming, source/export consistency, and representative real content.
