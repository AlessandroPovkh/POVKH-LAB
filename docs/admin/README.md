# Админка POVKH LAB

Редактор Decap CMS 3.16.3 уже работает локально. Подписки на CMS нет. Интернет-вход и автоматическая публикация подготовлены, но не подключены: домен и точный тип Timeweb ещё неизвестны. Никаких удалённых изменений эта настройка пока не делает.

## Попробовать сейчас

Из папки `site` запустите `npm run admin` и откройте http://127.0.0.1:4178/admin/. Нажмите «Войти», затем «Каталог и премьерный релиз». Локальный вход работает только на этом компьютере. Это не публичная админка без пароля.

1. Раскройте существующий релиз или нажмите «Добавить релиз».
2. Укажите название, артиста, дату и обложку JPG, PNG или WebP. Используйте имя файла латиницей без пробелов. Для сингла название трека и номер каталога сформируются автоматически.
3. Для вышедшего релиза добавьте подтверждённый жанр и хотя бы одну прямую ссылку на прослушивание. У анонсов эти поля могут оставаться пустыми.
4. Сохраните через «Опубликовать» → «Опубликовать сейчас». В локальной версии эта команда сохраняет **только отдельную копию на компьютере**, без публикации в интернете.
5. Премьерный релиз выбирается отдельно вверху. Новый релиз появится в списке после сохранения и перезагрузки редактора.

«Дата обновления каталога» определяет, какие релизы считаются вышедшими. При её переносе вперёд заполните жанр и ссылки для новых состоявшихся релизов. Публичный сайт сам по календарю не пересобирается. Авторские описания на трёх языках необязательны; новые релизы получают нейтральный текст из названия, артиста и даты. Состав артистов в этой версии выбирается из существующих профилей.

Локальные данные: `site/output/admin-sandbox/site/data/catalog.json`; загруженные обложки рядом в `site/assets/releases` внутри sandbox. Исходный каталог и текущий публичный просмотр от этих сохранений не меняются. Для переноса нужных правок разработчик копирует каталог и новые обложки из sandbox в `site`, затем запускает сборку и проверку. Тестовые записи после проверки удалены из sandbox.

Встроенный плеер хранит аудио отдельно: загрузка обложки и ссылки прослушивания не добавляет аудиофайл в плеер. Для новых полных треков пока нужна отдельная подготовка аудиобиблиотеки.

## Подключение после выбора домена

Схема: `/admin/` → вход через GitHub → черновик → «Опубликовать» → проверка GitHub Actions → Timeweb. Все изменения сохраняются в истории Git. Decap использует весь каталог как один документ; не редактируйте его одновременно в разных вкладках.

**Готовая серверная конфигурация рассчитана на Linux с SSH, Bash, GNU tar/mv и Node.js 22+.** Название «годовой» не подтверждает эти возможности. Для обычного виртуального хостинга нужно проверить SSH/символические ссылки и доступность Node-процесса. Если Node нет, сервер авторизации заменяется совместимым PHP OAuth-клиентом; он здесь не установлен и не проверен. Покупать второй сервер до уточнения тарифа не требуется.

1. Подключить реальный домен и HTTPS. Веб-корень направить на `<TIMEWEB_ROOT>/current`; каталог `<TIMEWEB_ROOT>/releases` должен принадлежать отдельному пользователю публикации. Существующий настоящий каталог `current` скрипт не заменяет. Все прошлые версии сохраняются.
2. Создать GitHub OAuth App: homepage `https://ваш-домен`, callback `https://ваш-домен/admin/auth/callback`. Пользователь GitHub должен иметь право записи в `AlessandroPovkh/POVKH-LAB`. Запрашивается `public_repo`, поскольку репозиторий публичный. Токен хранится Decap в браузере; после работы на чужом компьютере выходите из админки. Для приватного репозитория конфигурацию нужно пересмотреть.
3. Установить `deployment/timeweb/oauth.mjs` вне веб-корня, например `/opt/povkh-admin/oauth.mjs`. В закрытом файле `/etc/povkh-admin.env` (0600) задать `POVKH_SITE_ORIGIN`, `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`. Секреты не добавлять в Git, HTML или сообщения чата. Сервис и Nginx-примеры находятся рядом; адаптировать их под реальный сервер. OAuth слушает только 127.0.0.1:4180. Не включать принудительные expiring tokens: обновление токенов в этом варианте не реализовано, при истечении нужен повторный вход.
4. Создать GitHub environment `timeweb-production`. Secrets: `TIMEWEB_SSH_KEY`, `TIMEWEB_KNOWN_HOSTS` (ключ сервера проверить через панель Timeweb), `TIMEWEB_HOST`, `TIMEWEB_USER`. Variables: `TIMEWEB_PORT` (обычно 22), `TIMEWEB_ROOT`, `POVKH_SITE_ORIGIN`, подтверждённые `POVKH_CONTACT_EMAIL` и `POVKH_SOCIAL_*` из конфигурации сайта. Не отключать проверку SSH host key.
5. Проверить вход, черновик и первую публикацию на реальном домене. Только после настройки включить **repository variable** `TIMEWEB_DEPLOY_ENABLED=true`. Без неё workflow пропускается. Не включать одновременно прежнюю публикацию GitHub Pages для того же домена.

Сборка и QA завершаются до передачи файлов. Новая версия сначала загружается в отдельную папку, затем атомарно переключается `current`. Ошибка сборки или передачи оставляет прежнюю версию. Повторный запуск того же SHA намеренно не перезаписывает папку: после неудачной загрузки оператор проверяет её и удаляет только незавершённую папку либо создаёт новый коммит. Откат: `bash deployment/timeweb/activate.sh <TIMEWEB_ROOT> <предыдущий-SHA>` на сервере. Удаление старых версий автоматикой не выполняется.

## Проверки и ограничения

`npm run test:admin`, `npm run test:releases`, `npm run build`, `npm run check` из `site`. Проверены настоящая форма Decap, загрузка JPG, сохранение и перезагрузка. OAuth проверен на синтетическом обмене, без настоящего GitHub входа. Доставка в Timeweb пока не испытана на сервере; статус — готово к подключению, не «опубликовано».

Исходники Decap сохранены локально с лицензией и происхождением в `site/admin/vendor`, внешняя CDN для редактора не нужна.

Официальные инструкции: [GitHub backend](https://decapcms.org/docs/github-backend/), [черновики](https://decapcms.org/docs/editorial-workflows/), [OAuth-клиенты, в том числе PHP](https://decapcms.org/docs/external-oauth-clients/), [GitHub OAuth](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps).
